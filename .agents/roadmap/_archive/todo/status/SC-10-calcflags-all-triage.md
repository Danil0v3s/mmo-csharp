# SC-10 — Triage the remaining `CalcFlags: All` all-six-stat mis-mappings

> **Epic:** Status parity hardening · **Status:** ❌ Not started · **Size:** L · **Player-visible:** yes
> **Depends on:** none · **Blocks:** SC-07 (overlaps the generator-default review)
> **Filed by:** SC-02 on 2026-06-01 (the bulk per-SC triage it scoped but split out).

## Problem

The SC-flag generator collapsed rAthena's `CalcFlags: All: true` (a "recalc every
derived stat" *trigger*, not "buff all six base stats") into a literal six-base-stat
field list. SC-02 fixed the 7 highest-confidence offenders (4 weapon endows +
Incmatkrate + Siegfried + Nibelungen). **~35 more SCs** still map to all six base
stats (some via `StatusCalcFlagDefaults`, many via the bulk "Wave 58" explicit
`+Val1` all-six bodies in `StatusEffectRegistry`), and several are wrong.

## Current state (C#)

- `Map.Server/Status/StatusCalcFlagDefaults.cs` — entries still mapping to
  `{ Str, Agi, Vit, IntStat, Dex, Luk }` (post-SC-02). Get the live list with:
  `grep -nE 'CalcStatField.Str, CalcStatField.Agi, CalcStatField.Vit, CalcStatField.IntStat, CalcStatField.Dex, CalcStatField.Luk' StatusCalcFlagDefaults.cs`
- `Map.Server/Status/StatusEffectRegistry.cs` — the "Wave 58 — SC_X: +Val1 to
  listed CalcFlag fields" explicit bodies (e.g. `Providence`, `PowerOfGaia`, and
  others) that hard-code the six-stat buff.
- The candidate set (verify each against rAthena before touching):
  AllStatDown, Basilica, Catnippowder, Cheerup, Climax/ClimaxBloom/ClimaxCryimp/
  ClimaxEarth, Contents4, DeadlyDefeasance, Fortune, Harmonize, HeavenAndEarth,
  HiddenCard, HolyS, Incallstatus, Itemscript, Jumpingclan, Knowledge, Kyougaku,

**Explicitly NOT in this ticket:** the 12 Sorcerer `*Option` spheres
(CircleOfFireOption, CrystalArmorOption, EyesOfStormOption, FireCloakOption,

TidalWeaponOption, WaterDropOption, WaterScreenOption, WindCurtainOption) — those
are **SC-05**'s scope. And Marionette/Marionette2 already have bespoke bodies.

## rAthena reference

For each SC, open its `status.cpp` `status_change_start` arm + its `db/re/status.yml`
row. `CalcFlags: All` alone = recalc trigger. The real effect is whatever the start
arm stores (Val2/Val3) or which specific `SCB_*` it sets. Genuine all-stat SCs do
exist (e.g. `SC_INCALLSTATUS` = +Val1 to every stat) — keep those.

## Scope — every sub-system that must be touched

- [ ] **Add `CalcStatField.RecalcOnly`** (no-op sentinel) and, if any SC needs it,
      `CalcStatField.MatkRate` to the enum + a generator arm (RecalcOnly already
      no-ops since the switch has no default arm; document it).
- [ ] **Per-SC triage** of the ~35 candidates. For each, classify as one of:
  - genuine all-stat (keep the six-stat mapping — e.g. Incallstatus, likely
    Spirit/Truesight if rAthena adds to all stats),
  - sign-flipped debuff (AllStatDown / Harmonize subtract — needs `-Val1`/`-Val2`),
  - bespoke Val2/Val3 (e.g. Providence = race resist; see SC-04 consumer note),
  - or RecalcOnly (trigger only, no stat delta).
- [ ] **Replace the wrong ones** (StatusCalcFlagDefaults entry and/or the Wave 58
      explicit body) with the correct classification/body.
- [ ] **Producer of `StatusCalcFlagDefaults`**: the file is `<auto-generated>`.
      Update the generator's `All → RecalcOnly` rule + per-SC override table so a
      regenerate doesn't reintroduce the bug (see SC-02 history + the file header).
- [ ] **Completeness**: each reclassified SC keeps a valid handler (real body,
      correct generator field, or allowlist w/ `status.cpp:line` citation). Bump the
      `Generator_registered_at_least_N_SCs` bound if the count shifts.

## Done criteria

- No SC silently keeps the six-base-stat map unless rAthena genuinely buffs all six.
- AllStatDown / Harmonize apply the correct (negative) delta.
- Providence sets its race-resist Val (consumer = SC-04) rather than all-stat.
- A per-SC triage table is recorded in the PR description.
- `StatusEffectCompletenessTests` + `StatusEffectGeneratorTests` green.

## Test plan

- Parametrized test over the reclassified set: each applies its real effect at
  Val1=5 (or stores the cited Val2/Val3), base stats changed only when rAthena does.
- Sign tests for AllStatDown / Harmonize (stats go down).

- Many of these have a "Wave 58" explicit `+Val1` all-six body that must be deleted
  or rewritten (not just the StatusCalcFlagDefaults entry) — the explicit body wins

- Overlaps **SC-07** (generator-default magnitude review of the 159 linear-fallthrough
  SCs). Keep the scopes distinct: SC-07 = the +Val1 *linear* defaults that are
  plausibly right; SC-10 = the `All`-flagged all-six mis-mappings that are wrong.
