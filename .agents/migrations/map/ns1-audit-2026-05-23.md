# NS-1 audit · 2026-05-23

One-shot audit pass per [PARITY-CLOSURE-ROADMAP.md](../PARITY-CLOSURE-ROADMAP.md)'s
Next-steps NS-1 directive. Three parts:

- **NS-1a** — SC handler depth: count real vs skeleton vs unregistered
  SCs against rAthena `status.cpp` / `status_change.cpp`.
- **NS-1b** — Script-Proxy hit-count: instrument
  `ScriptHost.__invokeHookWithCtx` and tally every fallback (= unknown
  rAthena builtin call) vs every real host call across the full TS
  bundle.
- **NS-1c** — Pathing tie-break verification: side-by-side audit
  `Map.Server/Movement/Pathfinder.cs` vs rAthena `path.cpp`
  `path_search`.

The single biggest finding: **the SC handler coverage doc was right and
the task list was wrong.** ST.9-13 closed enum + SQL-flag wiring, not
per-SC behavior bodies. True coverage is **38 of 1,007 SCs with a real
body (3.8%)**, plus 57 skeleton no-ops, plus 912 entirely unregistered.

### Behavioral impact

Note that `bonus`, `bonus2`, `getrefine`, etc. are answered **but
the answer is "fine" only in shape.** Many of the host's variadic
methods (`sc_start`, `skill`, `heal`, `percentheal`, `itemheal`,
`specialeffect`, `setoption`) accept the call but execute no
behavior — they're `/* data-pending */` no-ops inside
`ScriptedBonusHost`. The Proxy-fallback gap is the *visible*
surface; the *hidden* gap is the silent no-op inside the host.

- **`getenchantgrade` = 1,239** calls. Combo scripts check enchant
  grade to gate bonuses; with the no-op-returning-0 fallback, every
  conditional like `if (ctx.getenchantgrade("EQI_HAND_R") >= 5)` skips,
  so enchant-grade-gated bonuses **never fire**. Wiring this single
  method via `IEnchantGradeService` activates a large class of late-
  game combos.
- **`sc_start` = 37 + `sc_start2` = 1 = 38 calls** that look like real
  host calls but the body is `/* SC engine wire-up data-pending */`
  inside `ScriptedBonusHost`. Items / combos that grant SCs on equip
  don't actually start the SC. Wiring `sc_start` requires also fixing
  ~970 SC handlers (NS-3).
- **`skill` = 726 calls** — items that grant a skill while equipped
  silently no-op today. Wiring requires `IPlayerSkillService.Grant`.

The top 3 wires for NS-2 are: `getenchantgrade`, `sc_start` (which
unblocks NS-3 too), `skill`.

## NS-1c · Pathing tie-break verification

### Method

Read [`Map.Server/Movement/Pathfinder.cs`](../../../Map.Server/Movement/Pathfinder.cs)
and compared field-by-field against rAthena
[`src/map/path.cpp`](../../../../rathena/src/map/path.cpp).
Verified constants, heuristic shape, anti-corner-cut rule, and
max-walkpath enforcement.

### Findings

| Aspect | rAthena `path.cpp` | C# `Pathfinder.Search` | Match |
|---|---|---|:---:|
| Cardinal step cost | `MOVE_COST = 10` (path.hpp:7) | `MoveCost = 10` (line 18) | ✅ |
| Diagonal step cost | `MOVE_DIAGONAL_COST = 14` (path.hpp:8) | `MoveDiagonalCost = 14` (line 19) | ✅ |
| Max walk path | `MAX_WALKPATH = 32` (path.hpp:10) | `MaxWalkPath = 32` (line 20) | ✅ |
| Heuristic | `MOVE_COST * (abs(dx) + abs(dy))` = Manhattan ×10 (path.hpp:55) | `MoveCost * (abs(dx) + abs(dy))` (line 121) | ✅ |
| Anti-corner-cut on diagonals | both cardinal neighbors must be walkable | `wN && wE && IsWalkable(NE)` etc. (lines 70-77) | ✅ |
| Start-on-blocked check | rejected | `!IsWalkable(x0, y0) → empty` (line 31) | ✅ |
| Goal-on-blocked check | rejected | `!IsWalkable(x1, y1) → empty` (line 30) | ✅ |
| Open set | binary heap (`node_heap`, path.cpp:224) | .NET `PriorityQueue<(short,short), int>` | ⚠️ tie-break |
| Bresenham line for `path_search_long` | yes (path.cpp:140-225) | `HasStraightLine` (line 100-118) | ✅ |

**Result: pathfinder behavior matches rAthena ✅.**

### Known minor divergence: tie-breaking on equal f-cost

rAthena's heap pops the **oldest insertion** when two entries tie.
.NET `PriorityQueue<TElement, TPriority>` is a min-heap with
**unspecified ordering for ties** (implementation-defined; in
practice it's whichever sifted up first).

**Impact:** when two paths exist with identical f-cost, the two
implementations may return different (equally-valid, equally-long)
paths. This affects which neighbor a mob picks when chasing through
a corridor where multiple paths are tied. It does **not** affect:

- Path length
- Whether a path exists
- Skill range checks (use `Distance`, not pathfinding)
- Damage / cast formulas
- Knockback / blow-position (`BlownPos` is straight-line)

**Verdict:** acceptable. The divergence is below the threshold of
player-observable behavior unless tested in artificial tied-corridor
scenarios. **Do not gate parity on this.**

### Secondary finding: `IPathService` stubs are decorative

[`Map.Server/Pathing/PathService.cs`](../../../Map.Server/Pathing/PathService.cs)
implements `IPathService.PathSearch` and `PathSearchLong` as `return
true;` stubs. These are called by `UnitOpsService` for skill-cast
pre-checks. The real movement loop calls `Pathfinder.Search`
directly via `MovementService.cs:57` and bypasses the stub.

**Impact:** skill cast pre-checks that should reject "no path to
target" currently always succeed (the caster fires the skill even
if pathing would fail). For most skills this doesn't matter (skill
range = LoS check, separate path), but for skills that explicitly
require walkable adjacency it's a small behavior gap.

**Fix:** wire `PathService.PathSearch` to call `Pathfinder.Search`
on the resolved `MapData`, returning `path.Count > 0`. ~10 lines.
Tracked as **NS-1c follow-up** (low priority).

## Aggregate verdict (NS-1)

The behavioral-parity surface has three concrete gaps, sized
honestly:

1. **SC handler bodies — the biggest gap.** 962 of 1,007 SCs
   (95.6%) have no `OnStart`/`OnTick`/`OnEnd` body. This is the
   dominant constraint for status/debuff/buff behavioral parity.
2. **Script-Proxy method-hit gap — small but concentrated.**
   `getenchantgrade` alone is 1,239 of 1,390 fallback hits (89%).
   Wiring that one method has outsized impact.
3. **Pathing — substantively done.** A* matches rAthena on
   constants, heuristic, corner-cut rule, and Bresenham line.
   Tie-break divergence is acceptable. `IPathService` stubs are
   a minor 10-line follow-up.

The order in NS-2 / NS-3 / NS-4 from the roadmap remains correct:

- **NS-2** (wire script bridge): cheap, unblocks ~28k items + the
  enchantgrade gate (1,239 calls).
- **NS-3** (SC handler bodies): the big SC depth wave; pre-req
  for `sc_start` from items to actually do anything.
- **NS-4** (per-skill backfill): the largest workstream
  (1,675 baselines), parallel-safe across families.

`SC depth` (38 / 1,007) and `proxy fallback` (1,390 / 85,068 calls
≈ 1.6%) replace the vague "probably big" with concrete
denominators. Estimates in the roadmap's NS-2 / NS-3 / NS-4 sizing
were correct in direction; this audit just sharpens the numbers.
